## Motivation

litespec has 11 domain-specific skills (explore, grill, propose, research, apply, review, fix, adopt, workflow, glossary, patch) — each injecting descriptions into the agent's context window every turn. Descriptions were already trimmed from ~2000 chars to ~565 chars, but the real problem isn't description length. It's **conceptual overhead and routing reliability**.

11 skills means the model classifies user intent into one of 11 buckets every turn, using only a ~50-char description per bucket. Several skills trigger on nearly identical intent — `explore` vs `grill` vs `workflow` all fire on "I want to think about my change." The model misroutes. Users don't think in workflow steps; they think "I'm working on a litespec change."

Additionally, `research` is a ceremony around something a competent agent does inline during implementation. No user thinks "time to research!" as a separate phase. Its one good idea — persist research as skill files — is two sentences in the build skill, not a standalone skill.

Similarly, `workflow` is a meta-skill that describes the system rather than doing work. Every other skill already runs `litespec status` at startup and self-routes. It's redundant.

## Scope

Collapse 11 skills to 4, organized along **behavioral stance** boundaries rather than workflow step boundaries:

| New Skill | Merges | Stance |
|-----------|--------|--------|
| `litespec-think` | explore, grill, workflow | No artifacts, freeform conversation |
| `litespec-plan` | propose, patch, adopt, glossary | Materialize structured artifacts to disk |
| `litespec-build` | apply, fix | Write code, run tests, fix failures, research knowledge gaps |
| `litespec-review` | review | Adversarial outsider, fresh eyes |

Changes involved:

- **`internal/paths.go`**: Replace 11 `SkillInfo` entries with 4. Remove IDs: explore, grill, propose, research, review, apply, adopt, workflow, glossary, patch, fix. Add IDs: think, plan, build, review.
- **`internal/skill/`**: Replace 13 template files (explore.go, grill.go, propose.go, research.go, review.go, apply.go, adopt.go, workflow.go, glossary.go, patch.go, fix.go, skill.go, skill_test.go) with 4 (think.go, plan.go, build.go, review.go) plus the existing skill.go and skill_test.go infrastructure. Delete: research.go, workflow.go, glossary.go, patch.go, fix.go, explore.go, grill.go, propose.go, apply.go, adopt.go, review.go. Create: think.go, plan.go, build.go, review.go.
- **`internal/skill/skill_test.go`**: Update `knownIDs` to the new 4 skill IDs plus artifact IDs.
- **`specs/canon/skill-generation/spec.md`**: MODIFIED requirements to reflect the new 4-skill set throughout (Template Missing Error, Skill Generation Tests, Skill Templates Reference Backlog, Glossary Skill Template, Apply Skill Glossary Reference, Fix Skill Registration, Fix Skill Workflow). REMOVED: research-specific requirements (Research Skill Registration, Research Skill Template, Research Skill Workflow).

### Why four and not fewer

- **One skill (44KB)**: Too fat. The model skips sections and conflates stances. Same routing problem, just moved from "which skill?" to "which section?"
- **Two skills (plan/build)**: Think and plan are genuinely different stances — one is freeform conversation, the other is structured artifact creation. Merging them causes the agent to start proposing when the user wants to explore.
- **Three skills (think/plan/build)**: Review's adversarial stance conflicts with build's builder stance. A skill file priming "write production code" and "adversarially attack production code" contaminates the context window before the first user token. Review needs its own priming context.
- **Four skills**: Non-overlapping descriptions, non-overlapping stances, no motivated reasoning. Each skill is focused enough for reliable routing, distinct enough for clean stance separation.

## Non-Goals

- Changing the CLI commands or flags. `litespec new`, `litespec patch`, `litespec validate`, etc. remain unchanged. Skills are agent-facing instructions, not CLI surface.
- Changing the underlying workflow (explore → grill → propose → apply → review → archive). The phases still exist; they're just routed within skills instead of between skills.
- Removing the glossary concept. It moves into `litespec-plan` as a section. The file `specs/glossary.md` and its usage are unchanged.
- Changing how `the-drill` or `skill-creator` work. Those are separate skills outside the litespec domain skill set.
